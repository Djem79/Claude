## 🔴 Critical

### 1. Cookie-баннер перекрывает конверсионные CTA на мобильных

`components/CookieBanner.tsx:53` — `fixed bottom-0 left-0 right-0 z-[60]`, рендерится
безусловно на всех публичных страницах (`app/layout.tsx`), без исключений по маршруту.

Замеры на **живом сайте** (`/properties/artistry-two-residences`, mobile viewport,
чистый контекст без localStorage):

| Элемент | z-index | top → bottom |
| --- | --- | --- |
| `MobileCtaBar` (Enquire + WhatsApp) | 40 | 670 → 757 |
| `CookieBanner` | **60** | 590 → **757** |

`document.elementFromPoint()` в точке кнопки «Enquire Now» возвращает элемент баннера.
То есть **каждый новый посетитель** (то есть вся органика) на самой конверсионной
странице сайта не может нажать заявку или WhatsApp, пока не закроет баннер. На десктопе
баннер частично перекрывает `FloatingCTA`, который CLAUDE.md называет «never remove».

**Фикс:** опустить баннер под CTA по z-index, либо сдвинуть по вертикали с учётом
высоты `MobileCtaBar`/`FloatingCTA` + `env(safe-area-inset-bottom)`, либо на страницах
с fixed-bottom CTA показывать баннер сверху.

### 3. `mail-watch.py` может молча терять алерты вахты

`scripts/mail-watch.py`:
- `telegram_send()` (строки 66-80) глотает любую ошибку отправки (`except Exception` →
  `print`) и ничего не возвращает;
- текст не обрезается и не чанкуется до лимита Telegram в 4096 символов;
- `write_state(new_state)` (строки 183-184) двигает курсор `last_uid` **безусловно**,
  независимо от того, дошло сообщение или нет.

**Сценарий:** сетевой сбой при отправке, либо накопившийся после простоя дайджест не
влезает в лимит → Telegram отвечает 400 → ошибка проглочена → курсор уехал → эти письма
не будут проверены **никогда**. Это единственный канал ловли PR/линкбилдинг-запросов
между сессиями, у которых дедлайн ~7 дней.

**Фикс:** чанкинг (как уже сделано в `competitor-gap.mjs`), `telegram_send` возвращает
bool, курсор двигается только при подтверждённой доставке.

### 4. `/add_keyword` стирает банк ключевиков при битом файле

`app/api/telegram-webhook/route.ts:397-405` — прощающее чтение (`try/catch` ловит и
ENOENT, и повреждённый JSON одинаково) с фолбэком `{keywords:[], index:0}`, который
тут же **записывается на диск**.

Это ровно тот паттерн, который CLAUDE.md называет по имени и отмечает как «shipped
twice». Два других писателя того же файла (`discover-keywords.mjs`, `competitor-gap.mjs`)
используют строгое `readBankStrict()` — этот путь до сих пор нет. Одна команда в момент,
когда файл недоступен/повреждён, теряет весь накопленный банк (~100 запросов от discovery
+ competitor-gap) и сбрасывает `index` в 0, из-за чего автоблог пойдёт писать дубликаты
уже отработанных тем.

**Фикс:** провести через `mutateJsonFile` (`lib/json-store.ts`) — примитив уже есть и в
рантайме Next доступен, в отличие от `.mjs`-скриптов.

### 5. Уязвимости зависимостей: `next` запинен на версии с HIGH-advisory

`npm audit` → **10 уязвимостей (6 high, 4 moderate)**. `package.json:14,27` — `next` и
`eslint-config-next` запинены как `"16.2.9"` **без caret** (единственные две зависимости
без `^`), поэтому `npm audit fix` их не трогает.

| Пакет | Сейчас | Фикс | Природа |
| --- | --- | --- | --- |
| `next` | 16.2.9 | **16.2.12** (патч) | Middleware/Proxy bypass **на Turbopack** (мы на нём собираем), DoS в Server Actions, SSRF |
| `postcss` (через next) | — | тот же апгрейд | XSS, path traversal, чтение файлов через sourceMappingURL |
| `brace-expansion`, `js-yaml` | — | `npm audit fix` | dev-only (линтер), без `--force` |
| `sharp` | ^0.34.5 | 0.35.3 (мажор) | унаследованные CVE в libvips |
| `nodemailer` | 8.x | 9.0.3 (мажор) | **уже осознанно отложено** в аудите 01.07 |
| `googleapis` | 144 | 173 (мажор) | только серверные cron, доверенный ввод |

Смягчающее обстоятельство по proxy-bypass: `/admin` защищён вторым слоем — каждая
страница делает `redirect(landingPath(...))`, каждый API-handler зовёт
`requireSection()`. Обход `proxy.ts` сам по себе доступа не даёт.

**Фикс:** `next` + `eslint-config-next` → 16.2.12 (патч-релиз, риск низкий, но нужен
`npm run build` + прогон прода), затем `npm audit fix` для dev-зависимостей.

## Проверено и признано чистым

- Auth/сессии: HMAC-SHA256, отдельный `SESSION_SECRET`, timing-safe сравнение,
  Origin-CSRF, `sections` читаются свежими из БД, а не из токена.
- Все 33 `route.ts`: каждый мутирующий handler защищён (`requireSection` / owner-only /
  HMAC / Basic Auth timing-safe), включая недокументированные `pf-webhook`, `pf-listing/*`.
- Загрузка файлов: magic-byte sniffing везде, path traversal структурно невозможен,
  download всегда `attachment` + `octet-stream`, preview — whitelist images+PDF.
- XSS: все `dangerouslySetInnerHTML` учтены; `formatInline` экранирует до разметки,
  ссылки — только внутренние; `escapeXml` в обеих RSS-лентах.
- Слой данных: `mutateJsonFile` корректен, все обёртки (`leads`/`properties`/`users`/
  `drafts`/`file-storage`) внутри критической секции, bcrypt вынесен за её пределы,
  коллизии id/slug разрешаются внутри секции. `prune-leads.mjs` делает полный бэкап

- Мониторы: частичные сбои SERP/LLM **не** считаются «выпадением из топа» (подтверждено
  и кодом, и тестом); `--sandbox` в `backlink-monitor`/`ai-visibility` реально

  районам чистая** — `AreasSection` (деривит), `llms.txt`, ROI-картинка для Telegram,
